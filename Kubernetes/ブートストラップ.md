## 1. runOracle.sh の場所はイメージ依存


これを付けないと：

* PID1がshellのままになる
* SIGTERMが正しく伝播しない
* graceful shutdownできない

* プロキシ設定をして
* パッケージを入れて

## 修正版 `bootstrap.sh`

```sh
#!/bin/sh
set -e

export HTTP_PROXY=http://proxy.example.com:8080
export HTTPS_PROXY=http://proxy.example.com:8080
export NO_PROXY=localhost,127.0.0.1,.svc,.cluster.local

# =========================
# パッケージインストール
# =========================
# Oracle Linux系の場合（例）
if command -v microdnf >/dev/null 2>&1; then
  microdnf install -y shadow-utils curl
elif command -v yum >/dev/null 2>&1; then
  yum install -y shadow-utils curl
fi

# =========================
# グループ・ユーザ作成
# =========================
getent group appgroup >/dev/null 2>&1 || groupadd -g 1001 appgroup
id appuser >/dev/null 2>&1 || useradd -u 1001 -g appgroup appuser

# =========================
# 権限調整（必要に応じて）
# =========================
# chown -R oracle:oinstall /opt/oracle/oradata

# =========================
# Oracleユーザで起動
# =========================

if command -v runuser >/dev/null 2>&1; then
  exec runuser -u oracle -- /opt/oracle/runOracle.sh
elif command -v su >/dev/null 2>&1; then
  exec su - oracle -c "/opt/oracle/runOracle.sh"
else
  echo "runuser / su が存在しません"
  exit 1
fi
```

## ポイント（重要）

### 1. `exec` を必ず使う

```sh
exec runuser -u oracle -- /opt/oracle/runOracle.sh
```

これにより：

* PID1 が OracleDB プロセスになる
* SIGTERM が正しく伝播する
* Kubernetes の graceful shutdown が正常動作

---

### 2. root → oracle の切替は「最後に1回」

途中で切り替えるのではなく：

```text
rootで全部やる
↓
最後にだけ oracle で起動
```

これが安定パターンです。

### 3. runuser / su の違い対応

環境依存を吸収：

| コマンド    | 備考             |
| ------- | -------------- |
| runuser | util-linux（推奨） |
| su      | ほぼ確実に存在        |

Oracle公式イメージでは通常：

```text
ユーザ: oracle
グループ: oinstall
```

が既に定義されています。
